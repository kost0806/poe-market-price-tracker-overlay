## 1. 목적

PoE 플레이 중 관심 있는 통화성 아이템(갑충석·정수·생기 등)의 시세를, 게임을 벗어나지 않고 화면 위에서 상시 확인한다.

---

## 2. 범위

### 1차 범위에 포함

- 고정 관심목록에 담은 통화성 아이템의 현재 시세 상시 표시
- 주기적 자동 갱신
- 게임 화면 위 오버레이 (**전체 클릭 통과 · 표시 전용**)
- **시스템 트레이 아이콘에서 여는 별도 설정 창** (관심목록 편집·설정 변경은 전부 여기서)
- 리그 전환, 갱신 주기 설정

### 1차 범위에서 제외

| 제외 항목 | 사유 |
|---|---|
| 이력 차트 / 시계열 축적 | API가 **절대 가격의** 시계열을 주지 않음. API가 계산해 주는 변동률은 **7일 창**이라 상시 감시용이 못 된다(4판에서 표시 제외 — FR-04-1) |
| 가격 알림 | 먼저 "보이는 것"을 완성한 뒤 실사용 후 판단 |
| 고유 아이템·스킬 젬·지도·착용 장비 | 모델이 복잡해지고 다른 API 형태가 필요 |
| 공식 Trade API 연동 | OAuth·레이트리밋·약관 제약. 스택 아이템엔 poe.ninja로 충분 |
| 한글 이름 표시 | **구조(i18n)는 1일차부터 넣되 사전은 나중에 채움** |
| 전역 핫키, 게임 프로세스 감지 | **감수한 비용이지 불필요가 아니다.** 게임이 화면을 덮은 동안에는 작업 표시줄이 게임 아래로 내려가 트레이 아이콘을 클릭할 수 없다(`docs/design/00-shell-measurements.md` §1.5 실측). 사용자가 Win 키·alt-tab으로 작업 표시줄을 띄운 뒤 클릭하는 것을 전제로 제외를 유지한다 |
| 배포 패키징·자동 업데이트 | 본인 전용 로컬 빌드 |

## 3. 용어

| 한글 | 영문 | poe.ninja 위치 |
|---|---|---|
| 갑충석 | Scarab | `Scarab` 카테고리 (115종) |
| 정수 | Essence | `Essence` 카테고리 (101종) |
| 생기 | Crystallised Lifeforce | **`Currency` 카테고리 안에 4종** |
| 혈기생기 | Vivid Crystallised Lifeforce | `vivid-lifeforce` |

> ⚠️ poe.ninja가 주는 카테고리 한글 라벨은 한국어 클라이언트 용어와 다르다.
> 예: Scarab → poe.ninja `"쇠똥구리"` vs 게임 내 `"갑충석"`. **기성 라벨을 그대로 쓰면 안 된다.**
>
> **이 경고는 유효하며, 해소된 것은 "그러면 어디서 받을 것인가"다.** 채택한 출처는 GGG 공식 한국 trade static API이고, 그것은 한국어 클라이언트 데이터로 GGG가 직접 생성하는 값이므로 이 문제가 원천적으로 발생하지 않는다 — `ambush-scarab` → `매복 갑충석`으로 실측 확인했다. 계약과 조인 규칙은 `docs/design/00-api-contract.md` §6이 정본이다.

## 4. 기능 요구사항

### FR-01 관심목록

- FR-01-1 사용자가 아이템을 **개별로 검색해 관심목록에 추가**한다. 추가·제거는 **설정 창**에서 한다 (FR-08).
  - **검색 대상은 받아 온 시세가 아니라 동봉된 아이템 카탈로그다**(개정 2026-08-17). 한 번도 조회하지 않은 카테고리의 아이템도 이름으로 찾히고 곧바로 관심목록에 추가된다 — 추가 시점에 그 카테고리를 1회 조회한다. 시세가 아직 없는 결과는 값 대신 **`시세 없음`**으로 표시한다. 카탈로그의 출처와 재생성은 `00-api-contract.md` §6.8.
  - 개정 전에는 검색이 **캐시에 있는 것만** 뒤졌다. 그 규칙 아래에서는 사전에 이름이 115개 들어 있는 갑충석을 검색해도 아무것도 나오지 않았고, 사용자가 먼저 "갑충석 카테고리를 조회한다"를 알아야 했다 — §3이 ⚠로 경고하는 "아이템→카테고리 매핑을 이미 알아야 한다"는 함정 그 자체다.
- FR-01-2 관심목록에서 아이템을 제거한다.
- FR-01-3 개수 제한 없음.
  - **오버레이는 클릭을 받지 않으므로 스크롤할 수 없다** (FR-05-2). 오버레이 창 높이를 내용에 맞춰 자동 조절한다(`heightMode=auto`일 때). 사용자가 명시적으로 높이를 고정하면(`heightMode=explicit`) 자동 조절하지 않으며, 화면에 다 들어가지 않는 행은 '외 n개 더' 표식으로 안내한다.
  - 설정 창의 관심목록은 스크롤한다 (FR-08-5).
- FR-01-4 관심목록은 설정 파일에 영속 저장되어 재시작 시 복원된다.
- FR-01-5 아이템 식별은 poe.ninja `id` 슬러그(`vivid-lifeforce`)를 키로 한다. 표시 이름이 아니다.

### FR-02 시세 조회

- FR-02-1 데이터 소스는 **poe.ninja 단독**.
- FR-02-2 조회 대상은 통화성 소모품 카테고리(exchange)에 한한다.
- FR-02-3 리그를 지정하지 않으면 현재 챌린지 리그를 사용한다.
- FR-02-4 리그 목록은 **런타임에 조회**한다. 리그명은 3개월마다 바뀌므로 상수로 두지 않는다.
- FR-02-5 폴링 시 **Divine Orb 시세(`Currency` / `id: "divine"`)를 항상 함께 조회**한다. 디바인 환산에 필요하다.

### FR-03 자동 갱신

- FR-03-1 기본 **15분** 주기로 폴링한다. 설정에서 변경 가능(최소 5분).
  - 초판은 5분이었다. poe.ninja가 공표한 이용 지침이 *"PoE 1 overviews roughly every 15 minutes … polling faster than a few minutes wastes bandwidth for no fresher data"* 라고 원본 갱신 주기를 밝혔다(`00-api-contract.md` §7.3). 5분 폴링은 **같은 값을 세 번 받는다.**
  - 최솟값 5분은 유지한다. 조건부 요청(NFR-02) 덕에 갱신이 없는 회차의 본문이 0바이트이므로, 사용자가 스스로 당겨 쓰는 것을 막을 이유가 없다.
- FR-03-2 관심목록에 담긴 아이템의 카테고리 단위로 묶어 호출한다. 아이템 하나당 한 번씩 호출하지 않는다.
- FR-03-3 실패 시 재시도한다(지수 백오프). 마지막 성공 값을 계속 표시한다.
- FR-03-4 값이 얼마나 오래됐는지는 `마지막 갱신 시각` 표시로 사용자가 판단한다.

### FR-04 표시

각 줄에 다음을 보여준다.

| 항목 | 형식 |
|---|---|
| 아이템 아이콘 | 이름 왼쪽에 한 칸 (FR-04-6) |
| 아이템 이름 | 영문 (i18n 계층 경유) |
| 현재가 | 아래 규칙 |
| 마지막 갱신 시각 | `2분 전` (화면 하단에 한 번) |

- FR-04-1 거래량(`volumePrimaryValue`)과 **변동률(`sparkline.totalChange`)** 은 표시하지 않는다.
  - 거래량은 처음부터 신뢰도 지표일 뿐이었다.
  - **변동률은 개정 4판에서 뺐다.** 실측 두 가지가 근거다(`00-api-contract.md` §3.2). ① **창이 약 7일이다**(§3.2.1) — 한 세션 동안 사실상 움직이지 않으므로 「상시 감시」에 아무것도 더하지 못한다. ② **기준 통화가 `core.primary`가 아니라 그 행의 `maxVolumeCurrency`다**(§3.2.2) — 표시 통화를 `카오스`·`디바인`으로 고정한 행에서는 가격과 변동률의 기준이 어긋나고, 같은 창에서 두 통화가 반대로 움직이면 **부호까지 갈린다.** 읽는 사람이 틀리게 읽을 수밖에 없는 수는 지운다.
  - **`Domain`은 값을 계속 보존한다** — 거래량과 같은 취급이다. 표시하지 않는 것은 뷰모델 위쪽의 정책이고, 파싱을 지우면 형식 변화 감지(G3)가 함께 사라진다.
- FR-04-2 저거래량 노이즈에 대한 별도 처리를 하지 않는다. 관심목록은 사용자가 직접 고르므로 감수한다.

#### FR-04-3 표시 통화 선택

아이템마다 실제로 거래되는 기준 통화가 다르다. 생기는 주로 디바인으로, 갑충석은 카오스로 거래된다.

- **아이템별로 `자동 / 카오스 / 디바인`을 선택**할 수 있다.
- 기본값은 **`자동`** 이며, 응답의 **`lines[].maxVolumeCurrency`를 따른다.** 이 필드가 곧 해당 아이템이 실제로 가장 많이 거래되는 상대 통화다. (초판 표기 `topPair.currency`는 raw API에 존재하지 않는다 — §6 정정 참조.)
  - 실측: 생기 3종 → `divine` · 갑충석 → `chaos` · 정수는 항목별로 섞임
- 전역 기본값도 설정에서 지정할 수 있다 (`자동` / `카오스` / `디바인`).

#### FR-04-4 현재가 표기 형식

선택된 통화 기준으로, 단가가 1 미만이면 역수로 표기한다. 생기처럼 개당 0.06카오스인 아이템은 그대로 띄우면 읽을 수 없기 때문이다.

| 선택 통화 | 조건 | 표기 | 예 |
|---|---|---|---|
| 카오스 | 1c 이상 & 1d 이상 | `359.7c (1.85d)` 병기 | 뿔 갑충석 |
| 카오스 | 1c 이상 | `43.5c` | Sacred 생기 |
| 카오스 | 1c 미만 | `1c당 15.5개` | 혈기생기 |
| 디바인 | 1d 이상 | `1.85d` | 뿔 갑충석 |
| 디바인 | 1d 미만 | `1d당 3,026개` | 혈기생기 |

#### FR-04-5 환산 정밀도

- 디바인 환산은 **`value.amount ÷ Divine Orb 시세`로 직접 계산**한다.
- **반올림된 환산 필드를 역수 계산에 쓰지 않는다.** 소수 4자리로 반올림된 값은 저가 아이템에서 오차가 10%까지 벌어진다.
  - 초판 관측(MCP 경유): 혈기생기 `valueAlt = 0.0003` → 역수 `3,333개` ❌
  - 직접 계산 `0.0644 ÷ 194.9` → `3,026개` ✅ (당시 `topPair.rate`와 일치)
  - **정정 (2026-08-15).** raw API에는 `valueAlt`가 **아예 없다.** 금지 대상 경로가 구조적으로 부재하므로 이 요구사항은 자동 충족된다. 다만 같은 성격의 대체 경로가 하나 있으므로 **함께 금지한다 — `core.rates.divine`의 역수.** 채택 경로는 `Currency` 응답에서 `id == "divine"` 행의 `primaryValue`이며, 검산은 `lines[].maxVolumeRate`로 한다(계산 입력으로 쓰지 않는다). 상세는 `docs/design/00-api-contract.md` §3.1.
- Divine Orb 시세는 `Currency` 카테고리의 `id: "divine"`에서 얻는다.

#### FR-04-6 아이템 아이콘 (개정 3판 신규)

오버레이 시세 행은 아이템 이름 **왼쪽**에 그 아이템의 아이콘을 그린다. 이름만으로는 행을 구별하는 데 시선이 오래 걸린다는 사용자 요청이다.

- 아이콘의 출처는 GGG trade static의 `entries[].image`이며, 앱과 함께 배포되는 **로컬 파일**이다. **실행 중 네트워크에서 아이콘을 받지 않는다** — 폴링 외의 트래픽을 만들지 않는다는 NFR-02의 정신과, 오프라인에서도 마지막 값을 그린다는 FR-03의 성격을 함께 지킨다. 재취득은 리그가 바뀔 때 `tools/`의 생성 절차로 한다.
- **아이콘이 없는 아이템이 있다.** 점술 카드는 GGG static이 개별 이미지를 주지 않으며, 게임에서도 전부 같은 아이콘을 쓴다(`00-api-contract.md` §6.6) — 따라서 점술 카드 전체는 **공용 카드 아이콘 하나**로 그린다. 그 밖에 아이콘을 찾지 못한 아이템은 **빈 자리를 유지**한다. 자리를 접으면 그 행만 이름이 왼쪽으로 밀려 목록이 어긋난다.
- 아이콘의 유무는 시세 표시에 영향을 주지 않는다. 아이콘을 읽지 못해도 행은 그대로 그려진다.

### FR-05 오버레이 동작 (표시 전용)

오버레이 창은 **오직 표시만 한다.** 어떤 마우스·키보드 입력도 받지 않는다.
관심목록 편집과 설정 변경은 전부 별도 설정 창에서 한다 (FR-08).

- FR-05-1 항상 최상위(`Topmost`)로 표시된다.
- FR-05-2 **전체 클릭 통과**: 창 전 영역에서 마우스 입력(클릭·휠 포함)이 게임으로 통과한다.
  - `WS_EX_TRANSPARENT`를 **상시 유지**한다. 커서 위치 감지나 부분 통과 상태기계를 두지 않는다.
  - 예외는 FR-05-6 위치 이동 모드뿐이다.
- FR-05-3 오버레이는 **절대 포커스를 갖지 않는다** (`WS_EX_NOACTIVATE` 상시).
  - 창을 클릭해도 게임이 최소화되지 않으며, 키보드 입력이 오버레이로 새지 않는다.
- FR-05-4 창 위치·크기를 저장하고 재시작 시 복원한다. 저장된 위치가 현재 모니터 구성에서 화면 밖이면 기본 위치로 되돌린다.
- FR-05-5 투명도를 조절할 수 있다. 조절은 설정 창에서 한다.
- FR-05-6 **위치 이동 모드**: 설정 창에서 켜는 동안만 오버레이가 클릭 통과를 해제해 드래그로 옮기고 크기를 바꿀 수 있다.
  - 끄면 즉시 전체 클릭 통과로 복귀한다.
  - 이동 모드 중에는 테두리를 시각적으로 표시해 현재 상태를 알린다.
  - 이동 모드 상태는 **저장하지 않는다.** 재시작 시 항상 꺼진 상태다.

### FR-06 설정

리그 · 갱신 주기 · 창 위치/크기 · 투명도 · 관심목록 · 표시 언어 · **표시 통화(전역 기본값 및 아이템별 설정)** 를 저장한다.

위치 이동 모드(FR-05-6)는 휘발성이므로 저장하지 않는다.

### FR-07 i18n

- FR-07-1 **모든 표시 문자열은 ID로 조회**한다. 코드에 리터럴을 직접 쓰지 않는다.
- FR-07-2 아이템 이름의 번역 키는 poe.ninja `id` 슬러그다.
- FR-07-3 1차 릴리스는 영문 사전만 채운다. 한글 사전은 이후 추가하며, **이때 코드 변경이 필요해서는 안 된다.**
  - **한글 사전의 출처는 GGG 공식 trade static API다** — `docs/design/00-api-contract.md` §6이 계약·조인 규칙·재생성 절차의 정본이다. poe.ninja는 어떤 매개변수로도 한글 이름을 주지 않는다(같은 문서 §2.0).
  - 사전은 **빌드 타임에 1회 생성**해 산출물을 저장소에 커밋한다. 런타임에 이 출처를 호출하지 않는다 — NFR-02와 어긋나고 앱을 kakaogames 가용성에 묶는다.
  - **「코드 변경이 필요해서는 안 된다」는 사전 파일 자체에 대한 조건이다.** 실제로 `ko.json`을 떨어뜨리는 데는 코드가 필요하지 않았다. 다만 그것을 확인하는 과정에서 **설정 창이 애초에 이 구조를 쓰고 있지 않았다는 사실**이 드러났다(FR-07-1 위반, `docs/design/03-lld-shell.md` §5.4.4). 그 수리는 한글 사전이 만든 요구가 아니라 이미 있던 결함의 상환이다.
- FR-07-4 UI 문구(버튼·라벨)도 동일한 방식으로 키를 갖는다.
  - **검색 결과의 카테고리 라벨과 리그 목록 상태도 여기에 포함된다.** 열거형 이름을 그대로 그리면 사용자에게 내부 토큰이 노출되고(`03-lld-shell.md` §5.4.3의 원칙), 어떤 사전으로도 번역되지 않는다.

### FR-08 트레이 아이콘 · 설정 창

오버레이가 표시 전용(FR-05)이 되면서, 모든 조작은 이 경로로 들어온다.

- FR-08-1 앱은 **시스템 트레이 아이콘**을 상주시킨다.
  - 오버레이 창은 `WS_EX_NOACTIVATE` 때문에 작업 표시줄에 나타나지 않는다. 트레이 아이콘이 **유일한 진입점**이다.
- FR-08-2 트레이 아이콘에서 **설정 창**을 연다. 설정 창은 **일반 창**이며 포커스를 받고 키보드 입력을 정상 처리한다.
  - 오버레이와 달리 클릭 통과·비활성화 스타일을 쓰지 않으므로, 검색어 타이핑이 게임으로 새지 않는다.
- FR-08-3 설정 창에서 하는 일 — 관심목록 검색·추가·제거(FR-01), 리그 선택, 갱신 주기, 표시 언어, 표시 통화(전역·아이템별), 투명도, **위치 이동 모드 토글**(FR-05-6).
- FR-08-4 설정 창을 닫아도 앱은 종료되지 않는다. 종료는 **트레이 메뉴에서만** 한다.
- FR-08-5 설정 창의 관심목록은 개수가 많으면 스크롤한다.
- FR-08-6 **첫 실행 시 트레이 아이콘 안내를 표시한다.** 근거는 두 가지 실측이다(`docs/design/00-shell-measurements.md` §4.1, §1.5).
  - Windows 11은 새로 등록된 트레이 아이콘을 **오버플로 플라이아웃에 숨긴다.** 도달에 클릭 두 번(셰브론 → 아이콘)이 필요하므로, 안내가 없으면 첫 실행 경험은 "아이콘이 보이지 않는다"가 된다. 안내는 **아이콘 고정(pin)을 권한다.**
  - 트레이가 유일한 진입점이므로(E1), 게임 중에는 **Win 키·alt-tab으로 작업 표시줄을 먼저 띄워야** 한다는 사실을 함께 알린다.
  - 안내는 1회성이며 이후 표시하지 않는다. 표시 여부는 설정에 영속한다.

## 5. 비기능 요구사항

- NFR-01 게임과 동시 실행되므로 유휴 시 CPU 점유가 무시할 수준이어야 한다.
- NFR-02 poe.ninja에 과도한 요청을 보내지 않는다. 카테고리 단위 호출 + 최소 5분 주기(기본 15분, FR-03-1).
  - **조건부 요청을 보낸다.** 카테고리별 마지막 `ETag`를 들고 `If-None-Match`로 재검증하며, `304`가 오면 직전 값을 그대로 쓴다. poe.ninja의 이용 지침이 명시적으로 요구하고(*"Use conditional requests and respect the cache headers; do not bypass caching"*), 실측으로 `304`·0바이트가 확인됐다(`00-api-contract.md` §7.4).
  - **요청은 자신을 밝힌다.** `User-Agent`에 앱 이름과 연락처(저장소 URL)를 싣는다 — 지침이 요구하는 항목이며, 차단이 필요할 때 poe.ninja 쪽에서 누구에게 말을 걸어야 할지 알 수 있는 유일한 단서다.
  - poe.ninja는 economy 엔드포인트를 **공식적으로 허용**하지만(같은 문서 §7.2), 데스크톱 앱은 자체 백엔드를 경유하라고 **권고**한다. 이 앱은 백엔드를 두지 않으므로(D2·G1) 그 권고를 따르지 못한다 — 대신 조건부 요청과 15분 기본 주기로 실제 트래픽을 지침 이상으로 줄이는 것이 그 자리를 대신한다.
- NFR-03 네트워크 실패가 앱을 종료시키지 않는다.
- NFR-04 게임은 **테두리 없는 창(Windowed Fullscreen)** 모드로 실행하는 것을 전제한다. 전용 전체화면에서는 어떤 오버레이도 표시되지 않으며, DirectX 훅 인젝션은 안티치트 위험 때문에 사용하지 않는다.
- NFR-05 poe.ninja는 GGG와 무관한 커뮤니티 사이트임을 앱 내에 출처로 밝힌다.

## 6. 데이터 소스 명세 (실측 확인)

> ⚠️ **필드명 정정 (2026-08-15).** 아래 표의 초판 필드명(`name` · `value.amount` · `valueAlt` · `volume` · `topPair` · `changePercent`)은
> **raw API에 존재하지 않는다.** 요구사항 수집 당시 poe MCP 서버를 경유했고 그 서버가 정규화한 이름을 기록한 것이다.
> 앱은 poe.ninja를 직접 호출하므로 초판 이름으로 구현하면 전 필드가 null이 된다.
> **필드 수준의 정본은 `docs/design/00-api-contract.md`가 갖는다.** 아래 표는 대응 관계를 담아 정정했다.
> §6의 수치·결론·금지사항은 모두 유효하며, FR-04-5 공식은 raw 필드로 재검증되었다.

**엔드포인트**

```
리그 목록   GET https://poe.ninja/poe1/api/economy/leagues
카테고리별  GET https://poe.ninja/poe1/api/economy/exchange/current/overview?league={league}&type={category}
```

리그 목록은 `[{id, name}, ...]` 평면 배열이며 **현재 챌린지 리그를 알려주는 플래그가 없다.** 첫 원소가 유일한 신호다.
구 엔드포인트 `/api/data/getindexstate`는 HTTP 404로 사용 불가.

**응답 구조** — 최상위는 `core`(메타·이름 사전)와 `lines`(시세 본체) 둘로 나뉜다.

| 용도 | 실제 raw 필드 | 예 | 초판 표기 (무효) |
|---|---|---|---|
| **안정적 식별자 & 번역 키** | `lines[].id` | `vivid-lifeforce` | `id` (동일) |
| 영문 표시명 | **`core.items[].name`** — `lines`에 없다. `id`로 **조인 필수** | `Vivid Crystallised Lifeforce` | `name` |
| 현재가 | `lines[].primaryValue` | `0.06401` | `value.amount` |
| 기준 통화 | **`core.primary`** — 항목별이 아니라 응답 전역에 하나 | `chaos` | `value.currency` |
| 디바인 환산 | **대응 필드 없음** | — | ~~`valueAlt`~~ |
| 신뢰도 지표 (1차 미사용) | `lines[].volumePrimaryValue` | `2097323` | `volume` |
| **주 거래 통화 판별** | `lines[].maxVolumeCurrency` | `divine` | `topPair.currency` |
| 검산용 비율 | `lines[].maxVolumeRate` | `3040` | `topPair.rate` |
| **변동률** (4판부터 **미표시**) | `lines[].sparkline.totalChange` | `30.46` | `changePercent` |
| 카테고리 역인덱스 | `core.items[].category` | `Currency` | (없었음) |
| 아이콘 (상대 경로) | `core.items[].image` | `/gen/image/...png` | (없었음) |

**exchange 카테고리 18종**

`Currency` · `Fragment` · `Runegraft` · `AllflameEmber` · `Tattoo` · `Omen` · `DjinnCoin` · `Ducat` · `EnshroudingCrystal` · `DivinationCard` · `Artifact` · `Oil` · `DeliriumOrb` · `Scarab` · `Astrolabe` · `Fossil` · `Resonator` · `Essence`

**주의**

1. **절대 가격의** 시계열 이력이 없다. 다만 `lines[].sparkline.data`에 **7점짜리 누적 변동률(%) 배열**이 있다.
   상대값이라 절대 가격 차트는 여전히 불가하나, 스파크라인은 저장 없이 그릴 수 있다 (§11 참고).
   **점 간격은 1일, 창은 약 7일이다** (실측 2026-08-18, `00-api-contract.md` §3.2.1). 그리고 그 변동률은 `core.primary`가 아니라 **`maxVolumeCurrency` 기준**이다(§3.2.2) — FR-04-1이 표시를 빼는 근거다.
2. **알 수 없는 카테고리를 요청해도 404가 아니라 HTTP 200 + 정상 형식의 빈 본문이 온다.**
   `{"core":{"items":[],"rates":{},"primary":"chaos","secondary":"divine"},"lines":[],"items":[]}`
   따라서 **HTTP 상태 코드로는 데이터 실패를 잡을 수 없다.** 응답 건전성 검사가 필수다.
3. `locale`을 지정해도 **아이템 이름은 영문으로만** 온다.
4. 기준 통화는 카오스다. 응답 전역의 `core.primary`가 이를 명시하며, 이 값이 `chaos`가 아니면 전제가 깨진 것으로 보고 거부한다.
5. 거래량이 낮은 항목의 변동률은 크게 튄다 (실측: volume 9.67 → `+65.71%`).
6. **디바인 환산은 반드시 `lines[].primaryValue ÷ divine 라인의 primaryValue`로 직접 계산한다.** → FR-04-5
   - 초판이 금지한 `valueAlt`는 **raw API에 아예 없으므로 위반 경로가 구조적으로 존재하지 않는다.**
   - 다만 `core.rates`(예: `divine: 0.005139`)는 **역수이고 반올림 폭이 문서화돼 있지 않아 같은 성격의 위험**을 가지므로 함께 금지한다.
   - 실측 검산: `0.06401 ÷ 194.6` → 역수 `3040.0` = API의 `maxVolumeRate` `3040`. 정확히 일치.
7. `lines[].maxVolumeCurrency`는 해당 아이템이 실제로 가장 많이 거래되는 상대 통화를 알려준다.
   표시 통화 `자동` 모드의 판단 근거로 쓴다.
   - 실측(Essence 104행 전수): `chaos` 96 / `divine` 8, 결측·null 없음. **값 공간이 닫혔다는 증거는 아니므로** 그 외 값은 `chaos`로 폴백한다.
