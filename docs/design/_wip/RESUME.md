## 4. 요구사항 없이 설계가 만들어 낸 표면 (사용자 판단 대기)

추적성 감사가 짚은 것. **승격하지 않고 보고만 한 상태다.**

1. **진단(Diagnostics)에 요구사항이 없다** — 롤링 로그 파일, 오류 링 버퍼, 「로그 폴더 열기」 버튼이 전부 설계 산물이다.
2. **설정 파손·쓰기 실패에 요구사항이 없다** — 격리 파일, 쓰기 차단 세션, `Acknowledge`, `settings.bak.json`.
3. **단일 인스턴스**(D18-d)는 NFR-02로 사후 정당화된 설계 발명이다.
4. `REQUIREMENTS.md` §8의 `settings.json` 예시가 낡았다 — `schemaVersion`·`window.heightMode` 누락.

## 5. 작업 방식 (유지할 것)

- **대용량 문서는 컨텍스트로 통과시키지 않는다.** 에이전트가 파일에 직접 쓰게 하고 요약만 받는다. 조립·검증은 스크립트로 하고 경계·개수·헤딩만 출력한다.
- **리뷰는 모아서 한 번에** 개정 에이전트에 넘긴다. 쪼개면 서로 충돌하는 수정이 들어온다.
- **승인 목록을 반드시 브리핑에 포함한다.** 없으면 개정 중 이미 옳은 결정이 부수 피해를 입는다(S2에서 실제로 발생).
- **측정이 문서를 이긴다.** 이 프로젝트에서 실측이 설계 주장을 **여덟 번** 뒤집었다. 프로브 프로젝트 24개가 `AppData\Local\Temp\claude\...\scratchpad\`에 있었으나 세션 종료로 소멸한다 — 필요하면 다시 만들 것.
